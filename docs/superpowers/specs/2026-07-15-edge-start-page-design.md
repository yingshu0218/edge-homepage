# Edge 启动页第一版设计

## 目标

构建一个替换 Microsoft Edge 新标签页的 Manifest V3 扩展。产品面向个人高频使用，核心体验是快速搜索、管理自定义书签、切换氛围主题，并通过 Edge 当前登录的 Microsoft 账号在设备间同步轻量配置。

第一版成功标准：扩展可在 Edge 开发者模式下安装；打开新标签页即可使用；刷新、重启和离线状态不会丢失数据；登录同一 Microsoft 账号且开启浏览器同步的设备能够同步书签、分组、主题和设置。

## 第一版范围

包含：

- 替换 Edge 新标签页。
- 搜索框，支持配置默认搜索引擎。
- 自定义书签的新增、编辑、删除、打开和拖拽排序。
- 以单层分组组织书签，分组可新增、重命名、删除和排序。
- 6–8 套内置图片主题，支持明暗外观、背景遮罩和模糊度等预设。
- 用户上传自定义背景；自定义图片仅保存在当前设备。
- 设置面板和同步状态反馈。
- 使用 `chrome.storage.sync` 同步轻量数据。
- JSON 导入和导出，用于手动备份与迁移。
- 为未来 VPS、GitHub 和 Gitea 同步预留 `SyncProvider` 接口。

不包含：

- 读取或镜像 Edge 收藏夹。
- VPS、GitHub 或 Gitea 同步实现。
- Microsoft OAuth 登录界面；同步身份直接跟随 Edge 浏览器配置文件。
- Markdown、图片或其他大文件的跨设备同步。
- 多级文件夹、标签系统、实时协作和复杂冲突合并。

## 视觉与交互

视觉采用已确认的“B × C”方向：以键盘效率和紧凑信息层级为骨架，融合渐变背景、玻璃卡片和氛围主题。装饰效果不得降低文字对比度或键盘可用性。

主页面包含：

1. 顶栏：产品标识、同步状态、主题入口和设置入口。
2. 核心区：问候语、时间日期和命令式搜索框。
3. 书签区：当前分组筛选、紧凑书签卡片、添加入口和拖拽排序。
4. 氛围区：当前主题信息及简洁同步摘要；窄屏时移至主内容下方或隐藏非关键文案。

键盘交互至少支持：聚焦搜索、提交搜索、关闭弹层、在常用控件间移动。所有可点击元素具有可见焦点态；弹层具有焦点约束与正确的可访问名称。动画遵守系统的“减少动态效果”设置。

## 技术架构

采用 React、TypeScript、Vite 和 Manifest V3。构建产物作为可加载到 Edge 的扩展目录。

模块边界：

- `domain`：书签、分组、主题和设置类型及纯业务规则。
- `storage`：本地存储、Edge 同步、导入导出和数据迁移。
- `sync`：`SyncProvider` 抽象、Microsoft/Edge 实现与同步状态机。
- `features/bookmarks`：书签和分组管理界面。
- `features/search`：搜索输入、引擎选择和 URL 判断。
- `features/themes`：内置主题、自定义本地背景和外观设置。
- `features/settings`：偏好、数据迁移和诊断信息。
- `newtab`：页面组合与扩展入口。

业务组件只依赖存储和同步接口，不直接调用 `chrome.*`，从而允许单元测试和未来替换同步后端。

## 数据模型

每个书签包含稳定 ID、标题、URL、可选图标信息、所属分组 ID、排序值以及创建和更新时间。分组包含稳定 ID、名称、排序值和更新时间。设置包含默认搜索引擎、当前主题 ID、外观参数和布局偏好。

同步数据包含模式版本号，并按记录或小数据块拆分，确保任何单项都低于同步存储单项配额。内置主题只同步主题 ID 和外观参数，图片文件随扩展安装包分发。

自定义背景以 Blob 存入 IndexedDB，只保存于本机；同步数据仅记录“使用本地自定义背景”的偏好。其他设备缺少对应图片时回退到默认内置主题并显示非阻断提示。

## 本地保存与 Microsoft 同步

用户操作首先保存到本地，界面不等待网络。同步实现使用扩展的 `chrome.storage.sync`，由 Edge 在用户登录 Microsoft 账号并启用同步时负责跨设备传输。离线时继续使用本地数据，恢复连接后由浏览器继续同步。

为控制约 100 KB 总配额、约 8 KB 单项配额及写入频率：

- 不同步图片、图标缓存和历史日志。
- 记录按 ID 或小块存储，不把全部数据塞入一个键。
- 高频拖拽和连续编辑经过防抖后批量写入。
- 写入前估算大小，并通过 `getBytesInUse` 监控占用。
- 达到预警阈值时提示用户清理或导出；写入失败时保留本地版本。

监听 `chrome.storage.onChanged` 接收其他设备的更新。由于个人使用且基本不会并发编辑，冲突采用记录级最后修改时间优先；删除记录保留有限期删除标记，避免旧设备恢复已删除内容。导入操作产生完整本地快照，并在用户确认后替换或合并。

同步状态包括：仅本地、等待同步、已同步、容量预警和同步错误。扩展无法可靠获知完整 Microsoft 账号状态时，只陈述可确认的存储结果，并引导用户检查 Edge 的个人资料同步设置。

## 主题资源

内置主题背景以 WebP 或 AVIF 随扩展打包，并提供适合桌面屏幕的尺寸。主题清单记录 ID、名称、资源路径、主色、文字色、遮罩和模糊参数。主题切换不产生网络请求。

第一版控制内置主题数量和资源体积，优先保证新标签页首次渲染速度。背景按需解码并预加载下一候选主题。用户自定义图片在导入时校验类型和尺寸，必要时在客户端缩放压缩后存入 IndexedDB。

## 错误处理

- URL 无效：阻止保存并在字段附近解释错误。
- 同步配额或限流：本地保存成功，显示可恢复状态并延迟重试。
- 同步数据损坏或模式未知：不覆盖本地数据，提供导出诊断和重置同步数据入口。
- 自定义背景读取失败：回退到默认主题，不影响书签与搜索。
- JSON 导入失败：在实际写入前完成格式与模式校验，展示具体错误。
- 删除分组：要求用户选择移动其中书签或一并删除，默认选择移动以避免数据丢失。

## 测试与验收

单元测试覆盖 URL 判断、排序、数据迁移、同步分块、配额估算、冲突选择和导入校验。组件测试覆盖书签增删改、分组切换、主题切换、设置保存和键盘操作。同步适配器使用模拟的扩展 API 测试写入失败、远端变化和离线状态。

浏览器验收覆盖：开发者模式安装、替换新标签页、本地持久化、不同窗口更新、自定义背景回退、导入导出，以及两台登录同一 Microsoft 账号且启用同步的 Edge 设备之间的数据传输。最终进行桌面常见宽度、窄窗口、明暗主题、键盘导航和减少动态效果的视觉检查。

## 后续扩展

未来同步服务通过 `SyncProvider` 接入，但不改变业务层数据模型。候选实现包括个人 VPS 的版本化轻量文件服务、GitHub/Gitea 备份，以及面向 JSON/Markdown 的通用个人同步服务。大文件同步与第一版 Edge 同步保持独立。
