# 搜索引擎选择与书签整卡拖拽设计

## 目标

修复书签卡片主体无法拖动的问题，并把设置中的搜索模板输入框改为易用的搜索引擎下拉菜单。Google 为默认选项，同时保留自定义搜索引擎能力。

## 搜索引擎选择

设置面板显示“搜索引擎”下拉菜单，内置：Google、Bing、百度、DuckDuckGo、Brave、搜狗、360 搜索和“自定义”。每个预设映射到一个包含 `%s` 的 HTTPS 搜索模板。

现有数据模型继续保存 `searchTemplate`，不改变 schema 版本。界面根据当前模板反查预设 ID；无法匹配任何预设时自动选择“自定义”并显示当前模板。选择预设后立即保存对应模板；选择“自定义”后显示模板输入框，只有通过 HTTPS/HTTP URL 与 `%s` 占位符校验后才保存。这样可兼容已有备份和同步数据，无需迁移。

## 书签拖拽

根因是 `useSortable` 的 activator listeners 仅绑定在卡片右上角的小按钮，用户拖动卡片主体不会启动拖拽。

修复后将 sortable attributes 与 pointer/keyboard listeners 绑定到整张书签卡片。PointerSensor 使用 6px 移动阈值，确保普通点击链接仍然打开网站，小幅手部移动不会误触拖拽。卡片在可拖区域显示抓取光标，拖动时显示位移、透明度和层级反馈；编辑、删除等按钮保持正常点击。

保留明确的无障碍拖拽名称和键盘拖拽能力。原小拖拽按钮不再作为唯一入口，可改为纯视觉提示或移除，避免重复焦点。

## 数据流与错误处理

- 搜索预设只改变现有 `searchTemplate`，继续走当前本地优先与 Edge 同步流程。
- 自定义模板无效时显示字段错误且不持久化。
- 拖拽只在目标书签有效且位置变化时生成新快照，继续使用现有排序规范化与 `updatedAt` 逻辑。
- 点击链接、编辑或删除不应触发排序更新。

## 测试与验收

- 单元/组件测试覆盖全部预设映射、Google 默认值、未知模板回退自定义、选择预设立即保存、自定义模板校验。
- 拖拽测试覆盖从卡片主体启动、移动阈值、正常点击链接、编辑/删除按钮、键盘拖拽和排序持久化。
- 在真实 Edge 中验证鼠标或触控板拖动整张卡片能够改变顺序，刷新后顺序保留。
- 运行全量测试、生产构建和 Manifest 验证。
