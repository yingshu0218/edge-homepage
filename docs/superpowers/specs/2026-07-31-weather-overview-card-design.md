# Day Start 常驻天气概览卡设计

## 目标

在启动页右栏“今日氛围”卡片下方增加常驻天气概览卡，让用户无需打开抽屉即可查看当天核心天气信息。使用浏览器当前位置时，将经纬度解析为真实城市名称，不再显示泛化的“当前位置”；界面同时明确标注天气与地点信息来源。

## 范围

本轮包含：

- 在桌面布局右栏增加常驻天气概览卡。
- 未配置天气时显示“设置天气”引导卡。
- 展示真实城市、当前天气、当前温度、体感温度、今日最高/最低、降水概率和未来 3 小时趋势。
- 点击天气概览卡打开现有天气抽屉。
- 使用当前位置时，通过 BigDataCloud 免费客户端反向地理编码接口将经纬度解析为城市或行政区。
- 卡片底部显示数据来源和更新时间。
- 更新扩展主机权限、隐私说明、自动测试和响应式样式。

本轮不包含：

- 新增地图、空气质量、日出日落或气象预警。
- 替换现有 Open-Meteo 天气数据源。
- 后台持续定位或位置历史记录。
- 跨设备同步天气地点。

## 页面布局

桌面宽度下，现有两栏工作区保持不变：

- 左栏继续显示标题、搜索和书签。
- 右栏改为纵向信息列，上方保留“今日氛围”卡片，下方放置天气概览卡。
- 两张卡宽度一致，使用相同的玻璃质感、边框、圆角和主题颜色体系。
- 天气卡使用语义化按钮容器，整张卡可点击，点击后打开现有天气抽屉。

窄窗口下，工作区继续切换为单列；天气概览卡位于“今日氛围”卡片之后，不与书签网格并排，也不产生水平页面滚动。

## 天气卡状态

### 未配置

卡片始终存在，显示天气图标、“查看本地天气”、简短说明和“设置天气”操作提示。点击卡片打开天气抽屉，用户可搜索城市或主动使用当前位置。

### 加载中

保留卡片尺寸，显示已选城市和“正在更新天气”，避免页面布局跳动。若已有缓存，则继续显示缓存数据并以小字注明正在更新。

### 已就绪

卡片展示：

- 顶部：城市名称、当前天气图标和天气描述。
- 主信息：当前温度。
- 辅助指标：体感温度、今日最高/最低、当天最高降水概率。
- 趋势：从当前时段开始的未来 3 个小时，每项显示时间、天气图标、温度和降水概率。
- 页脚：`天气：Open-Meteo · 地点：BigDataCloud` 与最近更新时间。

手动搜索城市时，地点名称继续来自 Open-Meteo Geocoding；页脚显示 `天气与地点：Open-Meteo`。使用当前位置时，地点名称来自 BigDataCloud，页脚显示两个来源。

### 失败与过期缓存

- 有缓存时继续展示缓存内容，并显示“更新失败，正在显示上次数据”。
- 没有缓存时显示轻量错误说明和“重试”提示；点击卡片仍打开天气抽屉。
- 反向地理编码失败时，天气请求仍继续。地点名称依次回退为行政区、国家，最后回退为“当前位置”；错误不阻断天气展示。

## 当前位置与城市解析

用户点击“使用当前位置”后：

1. 浏览器按现有流程请求一次当前位置。
2. 使用返回的 WGS84 经纬度调用 BigDataCloud 免费客户端反向地理编码接口，`localityLanguage` 设置为 ISO 639-1 的 `zh`。
3. 按 `city`、`locality`、`principalSubdivision`、`countryName` 的优先级选择可读地点名称。
4. 将解析后的名称与经纬度保存到现有 `WeatherLocation` 设置中。
5. 使用同一经纬度请求 Open-Meteo 天气数据。

扩展不持续监听位置，不保存定位历史，不把坐标写入天气来源之外的远程服务。反向地理编码只在用户明确点击“使用当前位置”时触发。

反向地理编码客户端必须：

- 使用独立接口与运行时响应校验。
- 对非成功响应、超时或缺少地点字段给出可恢复错误。
- 不引入 API Key、账号或额外运行时依赖。
- 通过扩展清单仅增加 BigDataCloud 所需的精确主机权限。

## 组件与边界

- `WeatherOverviewCard`：纯展示组件，接收天气状态、温度单位和打开抽屉回调；不直接发起网络请求。
- `reverseGeocodeClient`：将经纬度转换为地点名称并校验第三方响应。
- `WeatherDrawer`：保留城市搜索和定位入口；定位流程增加反向地理编码步骤。
- `App`：把现有 `useWeather` 状态传给概览卡，并保持顶栏天气摘要与抽屉状态互斥逻辑。
- `WeatherClient`：继续只负责 Open-Meteo 城市搜索与天气预报，不混入 BigDataCloud 逻辑。

## 数据与隐私

- 天气预报继续来自 Open-Meteo。
- 手动城市搜索继续把搜索词发送给 Open-Meteo Geocoding。
- 只有用户点击“使用当前位置”后，坐标才会发送给 BigDataCloud 以解析城市，并发送给 Open-Meteo 以获取天气。
- BigDataCloud 免费客户端接口会在处理请求时看到设备 IP 与当前坐标，并声明会以匿名聚合方式使用这些配对改进其 IP 定位数据；界面和隐私文档必须在用户触发定位前说明这一点。
- 不加入分析、广告、遥测或用户画像。
- README、安装说明和后续商店隐私文案必须准确描述两个服务及触发条件。

## 可访问性

- 天气概览卡使用原生按钮，辅助名称包含城市、天气状态和当前温度。
- 加载、缓存过期和失败状态使用可感知文本，不只依赖颜色。
- 未来三小时条目使用列表语义；天气图标提供文本描述。
- 键盘焦点样式与现有按钮一致，关闭天气抽屉后焦点返回触发概览卡或顶栏天气按钮。

## 测试与验收

自动测试覆盖：

- 未配置、加载中、已就绪、缓存过期、无缓存失败五种概览卡状态。
- 摄氏与华氏温度转换。
- 未来 3 小时截取、时间展示和降水概率。
- 点击概览卡打开天气抽屉并恢复焦点。
- BigDataCloud 响应校验、城市字段优先级、网络失败和无城市字段回退。
- 定位成功时保存解析后的城市名称；解析失败时仍能请求并显示天气。
- 扩展清单包含精确的 BigDataCloud 主机权限。
- 桌面与窄窗口布局无重叠、裁切或水平滚动。

Edge 实机验收覆盖：

1. 未设置天气时，红框位置显示引导卡。
2. 手动选择城市后，卡片显示城市与天气概览。
3. 点击“使用当前位置”并授权后，顶栏、概览卡和抽屉均显示真实城市。
4. 卡片底部可读地显示来源与更新时间。
5. 点击卡片打开天气抽屉，关闭后焦点返回卡片。
6. 重新加载扩展后，城市、单位和天气缓存仍然保留。
