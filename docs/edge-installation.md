# 在 Microsoft Edge 中安装 Day Start

Day Start 是本地优先扩展：书签、分组和设置会先保存在当前设备，再通过 Edge 同步存储传到登录同一 Microsoft 账户且已开启扩展同步的设备。同步失败不影响本地使用，JSON 导出与导入仍可作为独立备份。

## 1. 生成扩展目录

在项目根目录运行：

```bash
npm install
npm run build
```

构建完成后不要移动或删除项目中的 `dist/` 目录；Edge 将从这个目录读取扩展。

## 2. 以开发者模式加载

1. 在 Edge 地址栏打开 `edge://extensions`。
2. 打开页面左侧的“开发人员模式”（Developer mode）。
3. 选择“加载解压缩的扩展”（Load unpacked）。
4. 在文件选择器中选择本项目的 `dist/` 目录。
5. 确认扩展列表出现 **Day Start**，且没有错误提示。
6. 打开一个新标签页；页面应显示 Day Start，而不是 Edge 默认新标签页。

修改代码后重新运行 `npm run build`，再回到 `edge://extensions` 点击 Day Start 卡片上的“重新加载”。重新加载不会清除本地数据；卸载扩展可能会清除数据。

## 3. 权限与网络说明

构建后的清单仅请求以下权限：

| 权限或范围 | 用途 |
| --- | --- |
| `storage`、`unlimitedStorage` | 在当前设备保存数据，并通过 Edge 同步书签、分组和设置。 |
| `geolocation` | 仅在用户点击“使用当前位置”时调用浏览器定位，并由 Edge 显示授权提示。拒绝后仍可搜索城市。 |
| `https://geocoding-api.open-meteo.com/*` | 用户输入城市名称时查找城市。 |
| `https://api.open-meteo.com/*` | 为已选择的城市获取天气预报，或在用户手动刷新时更新；Open-Meteo 会收到用于天气查询的坐标。 |
| `https://api.bigdatacloud.net/*` | 仅在点击“使用当前位置”并取得当前位置后，使用当前坐标解析地点。 |

手动搜索城市时，Open-Meteo 会收到城市查询；只有点击“使用当前位置”后，Edge 才会显示定位授权请求，拒绝后仍可搜索城市。BigDataCloud 仅在该操作取得当前位置后收到当前坐标；BigDataCloud 说明其免费客户端端点会观察请求 IP 和当前坐标，并使用匿名聚合的 IP 与坐标配对来改进 IP 地理定位。概览卡片页脚会标明当前使用的数据来源。

Day Start 不会持续追踪位置，也不保存位置历史；不使用 API 密钥、分析、广告或独立账户，不请求书签或标签页访问权限。书签、分组和设置使用 Edge 提供的扩展同步存储；天气、站点图标和自定义背景仅保存在本机。重新加载已解压缩的扩展后，Edge 可能会提示确认新增的 BigDataCloud 主机权限。书签卡片还可能访问书签原始来源的 `/favicon.ico`（例如 `https://<bookmark-origin>/favicon.ico`）来显示图标；请求失败时在本地回退为首字母图标。

## 4. 单设备功能验收

重新加载扩展后依次检查：

1. 新建一个书签，重新加载扩展后确认该书签仍存在；网站图标无法加载时应显示首字母回退。
2. 在“设置”中将“每组显示书签”分别改为 8、12、16，确认当前分组网格按所选数量显示；超出的书签可通过“管理书签”查看。
3. 打开“管理书签”，按名称或网址搜索，编辑一个书签，并选择多个书签执行移动和删除；再打开“打开排序管理”调整顺序，关闭后顺序应保持。
4. 点击分组栏的“管理”，新建并重命名一个分组；删除非空分组时应能选择移动书签或一并删除。
5. 点击顶栏时间，确认显示与设备本地时间一致；切换 12/24 小时制、秒数和完整日期后重新打开新标签页，设置应保持。
6. 打开天气，搜索并选择一个城市，确认显示实况、未来 12 小时和未来 5 天预报。点击“使用当前位置”时才应出现定位授权请求；拒绝请求后仍可搜索城市。
7. 在已获得天气后使设备离线，再打开天气或刷新：已缓存的天气应继续可见；如果刷新失败，页面应保留上次数据并显示可恢复的错误提示。天气缓存的有效期为 30 分钟。
8. 在设置中导出 JSON。在另一份本地数据上分别尝试“替换现有数据”和“合并数据”导入，确认导入前显示分组和书签数量并要求确认。
9. 确认顶栏从“正在同步…”变为“已同步”；断网或同步异常时，应显示已保存在本机且同步失败，其他功能仍可使用。

## 5. 验证 Edge 跨设备同步

1. 在两台设备的 Edge 中登录同一 Microsoft 账户，并开启扩展同步。
2. 从 Edge 商店安装同一版本的 Day Start。
3. 在设备 A 新建书签或分组，等待顶栏显示“已同步”。
4. 在设备 B 打开新标签页，确认数据自动出现；再修改一个名称并等待同步。
5. 回到设备 A 打开新标签页，确认修改已合并。站点图标和自定义背景不会跨设备传输，各设备会自行缓存或回退显示。

## 6. 使用 JSON 在设备间迁移或备份

1. 在原设备打开 Day Start 的“设置”，点击“导出备份”。
2. 将生成的 JSON 文件通过你信任的方式传到新设备。
3. 在新设备按上文步骤加载 Day Start，打开“设置”，选择 JSON 文件。
4. 选择“替换现有数据”以用备份覆盖当前数据，或选择“合并数据”以保留当前记录并导入 ID 不重复的记录。
5. 核对确认区显示的分组和书签数量后点击“确认导入”。

备份包含版本号；受支持的旧版本会在导入时自动迁移。JSON 文件含有你的书签和设置，请像其他个人备份一样妥善保存。

## 7. 已知边界

- 部分网站不提供根路径 `favicon.ico`，此时显示首字母图标。
- 天气数据来自 Open-Meteo；离线时不会获得新预报，但会优先显示本机缓存。没有已缓存天气时，需恢复网络或选择城市后再试。
- 当前不读取 Edge 收藏夹，也不向自建云端、VPS、GitHub 或 Gitea 传输数据。
- `npm run dev` 适合样式开发，但本地存储、定位权限和天气请求必须在扩展环境测试。

## 8. 卸载或恢复默认新标签页

打开 `edge://extensions`，关闭或移除 Day Start。再次打开新标签页即可恢复 Edge 默认页面。卸载扩展会删除其本地数据；如需保留书签和设置，请先导出 JSON 备份。
