# Day Start

Day Start 是一个面向 Edge 的本地优先新标签页扩展。它提供分组书签、主题、自定义背景、设备本地时钟、天气和 JSON 备份迁移。书签、分组和设置会先保存在当前设备，再通过 Edge 同步存储传到登录同一账号且已开启同步的 Edge；断网或同步失败时仍可正常使用。

## 功能

- 替换 Edge 新标签页；首页可跨分组搜索书签标题和网址，支持基础缩写匹配、↑↓ 选择、Enter 打开、Esc 关闭，同时保留网址直达与网页搜索。
- 首次无打开记录时显示全部书签；记住本机上次选择的有效分组。添加书签后自动切到目标分组，即使超过显示上限也会立即显示新书签并提示保存结果。
- 新建、编辑、删除书签；网站图标加载失败时自动回退为首字母图标。
- 每个分组可选择显示 8、12 或 16 个书签；超出的书签可在“管理书签”中查看。
- 完整书签管理器支持按名称或网址搜索、编辑、批量移动、批量删除和排序管理；分组也可新建、重命名、排序和安全删除。
- 六套内置图片主题，以及只保存在当前设备上的自定义背景。
- 顶栏时钟使用设备本地时间，可设置 12/24 小时制、秒数和完整日期。
- 城市天气由 Open-Meteo 提供，支持城市搜索、摄氏/华氏切换和用户主动请求当前位置。
- 书签、分组和设置通过 Edge 原生同步存储自动合并到其他设备，本地保存不依赖同步成功。
- 版本化 JSON 备份支持导出、替换导入和合并导入，可用于设备之间的手动迁移；兼容的旧备份会在导入时迁移。

## 数据、网络与隐私

Day Start 的书签、分组和设置同时写入扩展本地存储与 Edge 同步存储；天气缓存写入扩展本地存储，书签图标与自定义背景写入当前设备的本地 IndexedDB。重新加载扩展或关闭 Edge 不会清除这些数据。同步不可用时，本地保存不受影响；卸载扩展通常会清除本地数据，因此仍建议先导出 JSON 备份。

Edge 同步由浏览器和用户的 Edge 账号管理，Day Start 不读取账号身份，也不运营独立账号或自建同步服务器。登录同一账号并开启同步的 Edge 会接收同步区中的书签、分组和设置；自定义背景、天气缓存和书签图标不会跨设备传输。JSON 导出、替换导入和合并导入仍可作为独立备份与手动迁移方式。

天气功能声明了 Open-Meteo 和 BigDataCloud 的 API 主机权限：手动搜索城市时，Open-Meteo 会收到城市查询；选定城市、打开已配置天气或手动刷新时，Open-Meteo 会收到用于天气查询的坐标。只有点击“使用当前位置”后，Edge 才会显示定位授权请求；取得当前位置时，BigDataCloud 才会收到当前坐标以解析地点，拒绝授权不会影响城市搜索或其他功能。BigDataCloud 说明其免费客户端端点会观察请求 IP 和当前坐标，并使用匿名聚合的 IP 与坐标配对来改进 IP 地理定位。天气结果会在本机缓存 30 分钟；网络离线或刷新失败时，如有已缓存结果，页面会继续显示上次天气并提示刷新失败。概览卡片页脚会标明当前使用的数据来源。

Day Start 不会持续追踪位置，也不保存位置历史；不使用 API 密钥、分析、广告或账户。重新加载已解压缩的扩展后，Edge 可能会提示确认新增的 BigDataCloud 主机权限。

书签图标通过浏览器的扩展 favicon API 获取，并缓存在本机 IndexedDB 中。缓存图标会立即显示，每 7 天在后台更新一次；获取失败时保留旧图标，并在 24 小时后重试。没有可用图标时会在本地回退为首字母图标。

书签卡片与首页搜索使用同一套本机打开统计，显示最近 24 小时、7 天、30 天和累计次数；“最近常用”也按本机记录排序。详细点击时间与累计次数仅保存在当前设备，**不写入 Edge 同步存储，不跨设备汇总**。每次打开该书签时会清理 30 天以前的详细时间，累计次数继续保留；搜索网页、直接输入网址不会增加书签计数。

加载后的数据与新导出的 JSON 备份使用 schema 3：书签内容和 `bookmarkUsage` 分开。扩展本地存储分别使用内容项 `app:snapshot` 和统计项 `app:bookmark-usage:v1`，点击只更新后者；同机标签页通过 Web Locks 串行更新，普通内容保存也会保留已经落盘的较新计数。读取 schema 1/2 的本地数据或 JSON 备份时，原有统计会完整迁到本机表中，书签、分组与设置均保留；下次保存时写入新格式。读取旧 Edge 同步记录时，只有本机尚无该书签统计才会用旧统计初始化一次，随后以本机记录为准，不重复累计。合并导入保留现有同 ID 的书签及统计，追加新 ID 的内容和统计；替换导入恢复备份中的内容和统计。新备份需用本版本或更新版本导入。

Edge 同步继续兼容原有 schema 2 的内容格式，但只传书签内容、分组与设置；点击不会改动书签的 `updatedAt`，也不会触发同步写入，避免统计压过其他设备上的内容编辑。所有设备应升级到本版本：旧版仍会把点击当作内容修订，无法从旧数据追溯出真实的编辑时间。同步写入前仍检查每项 8,192 字节、总量 100 KiB 和最多 512 项的边界，过长内容或过多书签会提示同步失败，本地内容和 JSON 导出不受影响。配额依据见 [Chromium storage API](https://developer.chrome.com/docs/extensions/reference/api/storage)。

## 本地开发

需要 Node.js 22.12 或更高版本。本轮验证环境为 Node.js 26.8.2、npm 11.19.1；测试会显式使用 jsdom 的浏览器存储，不依赖 Node 的实验 Web Storage 开关。普通网页预览会使用浏览器本地存储模拟本机数据，便于界面开发，但不会伪装 Edge 同步状态；完整同步功能请使用 `dist/` 在 Edge 中加载验证。

```bash
npm install
npm run dev
```

验证生产构建：

```bash
npm test
npm run build
```

`dist/` 是可直接加载到 Edge 的扩展目录。加载、权限说明、离线天气和 JSON 迁移步骤见 [Edge 安装与本地数据验证](docs/edge-installation.md)。
